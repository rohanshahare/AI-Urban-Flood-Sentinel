The final MP4 is `video_demo/AI_Urban_Flood_Sentinel_Demo.mp4`. It uses the genuine dashboard capture at `recordings/page@d736c533230fd36565d240c14d9998dd.webm`, locally generated paragraph voice clips, phrase captions, and an eased nine-shot camera plan.

## Assets

- `../AI_Urban_Flood_Sentinel_Demo.mp4` — the final deliverable.
- `../captions.srt` and `captions.srt` — identical phrase-caption tracks (77 cues, last cue ends at 149.4 s); the top-level copy is the one referenced by the demo docs, the render burns in this directory's copy.
- `../narration_script.md`, `../shot_list.md`, `../production_plan.md`, `../recording_checklist.md` — planning documents.
- `narration.txt` — the authoritative nine-paragraph spoken script.
- `narration.wav` (149.4 s) and `paragraph-01.wav` … `paragraph-09.wav` — concatenated narration and its per-paragraph clips; the render reads each clip's duration to time the nine shots.
- `recordings/page@d736c533230fd36565d240c14d9998dd.webm` — the 139.48 s, 1920×1080, 25 fps VP8 dashboard capture used as picture source.
- `generate_audio.ps1`, `assemble.ps1`, `render_demo.cjs`, `record_demo.cjs` — the pipeline scripts.
- `camera_plan.md` — shot timing and motion, regenerated by every render.
- `validation_report.md` — measured render properties and review scope.

Intermediate review frames (`check_*.png`, `review_*.png`, contact sheets), unused capture takes in `recordings/` and timing-test WAVs are intentionally not tracked; see the repository `.gitignore`.

## Reproduction

Requires Windows (Microsoft Zira Desktop speech), FFmpeg, Node.js, and — for re-recording the dashboard — Playwright plus Microsoft Edge with the backend running. To re-render from the tracked capture:

1. Run `powershell -ExecutionPolicy Bypass -File video_demo/production/generate_audio.ps1` to synthesize narration and timed captions with Microsoft Zira Desktop.
2. Run `powershell -ExecutionPolicy Bypass -File video_demo/production/assemble.ps1` to render the final 150-second MP4 with FFmpeg.

The scripts use the bundled machine-local Node/FFmpeg paths by default. Override the Node executable by passing `-Node` to `assemble.ps1`; edit the FFmpeg path in `render_demo.cjs` when reproducing on another machine. `record_demo.cjs` re-records the dashboard only if a new capture is wanted; the render does not require it.

## Known limitations

- Speech is machine-local Windows TTS; a different voice or machine produces different clip durations and therefore different shot timing (the render derives both from the WAVs, so it stays self-consistent).
- Reproduction is scripted but not fully portable: the Node and FFmpeg paths in `assemble.ps1` / `render_demo.cjs` are absolute and machine-specific until edited.
- Loudness and peak were measured, but no perceptual listening test was available; naturalness is not claimed as independently verified.
- Captions are burned in; players that read `captions.srt` will show the same cues a second time.
